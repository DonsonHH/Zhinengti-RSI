# 最小复现与研究摘要

## 当前问题和方法

研究问题是：在部分观测和持续重访约束下，额外检查一个任务时，怎样显式呈现它对后续检查机会的影响？

本轮将确定性排班与不确定性风险评分分开。静态图、服务时间和所属巡回给出两个反事实时间表；公开合格测量、趋势、检查年龄和同Pod联系给出透明风险代理；另一个离线模块读取真实窗口解释已发生的得失。

已得到的机制证据：两条8301轨迹中108都提前30秒确认，但其他任务正常完成晚30秒，分别多漏1、2段。七个已存方法分支的728个剩余完成时刻，与独立Dijkstra和实际事件相同。原型在8300提前确认冷却异常的动作上也给负分，显示风险尺度和公开观测缺失仍影响选择。

## 创新边界与证据

这是对B2已知失败的最小开发诊断，不是新策略泛化实验。路线时间表、风险暴露评分、60秒否决候选均由人工设计，没有新的PPO、CVAE、Qwen或递归改进贡献。

该接口可为后续“公开机会代价感知的工具调用”研究提供可审查对象。它与现有重访规划、部分观测主动检查和改进器方法的具体差异仍待模型级文献比较，当前不声称已建立创新性。原论文绑定与既有相关工作继续沿用此前记录。

## 本地重做诊断

需要Python 3.11以上和NumPy，使用仓库根目录。该命令只重算旧记录的队列和统计，不生成物理过程、不加载神经模型。`--output`必须是新的目录，避免覆盖已有结果。

```powershell
$env:PYTHONPATH='src'
python scripts/diagnose_queue_cost.py `
  --evidence research/2026-10-29-m12c1b2-confirm/evidence `
  --output .work/queue-diagnosis-reproduction
python -m unittest discover -s tests -p test_queue_diagnostics.py -v
python scripts/verify_queue_diagnosis.py --workspace . --output .work/queue-diagnosis-verification.json
```

源码接口：

- `QueueState`仅含公开测量和已知队列状态。
- `diagnose_queue(plan, state, target)`返回目标提前量、后续完成计划、整回合顺延暴露和返回证书。
- `collateral_proxy(plan, state, diagnostic)`独立输出公开估计值；目前仅有专业历史适配，不等同原B2完整公开输入。
- `history_state(...)`只接受当前派单前的assignment和不晚于当前的合格测量；对未来记录、忙碌执行者、校准／专业不匹配直接拒绝。
- `queue_oracle.offline_oracle(...)`只供离线解释。在线诊断模块不导入它，也不把其输出返回给候选选择。

本轮复现只需要仓库已有示例和失败轨迹。完整B2神经／物理重放仍需其原模型及全部数组，不能将这里的精简重算当作替代。

审查修正后的本地完整测试发现202项，182项执行通过，20项因缺少Torch跳过，无失败或错误；其中新增14项诊断测试全部通过。[完整测试记录](evidence/local-full-tests.json)逐项列出跳过原因，原B2的188项无跳过集群记录单独保留。
