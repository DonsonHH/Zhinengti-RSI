# 公开信息与时序接口审查

本轮基线为`b5e66de76f6b604859f98c00b10cdd8f05fd864f`。修改前重新执行B3便携核验，七个旧分支的728次排班核对及两条8301失败诊断一致。所有3,897个原有Git跟踪文件的散列已保存，新实现另起模块，不改B2/B3结果或旧接口。

## 1. 156号任务为何丢掉了线索

`queue_history.history_state`只接收已完成的专业测量。8300冷却156在370秒时，最近专业流量检查是130秒，读数36.002709kg/s，年龄240秒。按33.6kg/s合成阈值，这个旧读数不产生异常信号。

B2的`FacilityObserver`还接收当前公开流量遥测。156属于12号Pod，处于偶数Pod遥测范围，370秒已有**8.711502kg/s**的新流量读数。B2在当时实际使用它，得到`1−8.711502/33.6 = 0.740729`的风险代理。

旧适配器没有接收这份遥测，而不是CVAE或流量模型没有产生线索。新接口分别保存专业读数与当前有效流量，原件、时间和缺测原因同时存在。

## 2. 新接口保存哪些来源

`causal_observation.capture_public`是唯一读取环境的适配器，输出闭合白名单`causal-public-v1`；在线`public_stopping`仅接收这个普通数据结构。

| 字段 | 来源和时间定义 | 缺失时 |
|---|---|---|
| `qualified` | 对该任务最近一次合格专业检查；保留原单位与完成时间 | `available=false`，数值／时间均为`null` |
| `temperature_measurement` | 最近已取得的远程或专业温度；时间取真实测量印记 | 不使用初始50°C冒充已测 |
| `flow` | 观测器已取得的最新流量；当前远程流量标记`remote_flow`，其余标记专业流量 | 不把观测器名义初值当读数 |
| `contact`、`sensor_error` | 同Pod已经完成的电气／控制专业测量 | 未完成相应检查则不可用 |
| `nominal` | 因果名义模型当前输出，预测目标与截止均为当前时刻 | 不使用物理真值替代 |
| `cvae_raw` | 包装冻结预测器，记录实际条件先验均值输出和调用时刻 | 尚无真实调用，或普通旧环境未安装记录器，则不可用 |
| `history_assimilated` | 既有CVAE输出经已完成测量覆盖后的缓存值；标明模型刷新或较新测量时刻 | 首次模型刷新前不把初始缓存当CVAE预测 |
| `telemetry` | 同时刻公开需求／实际功率、泵指令、一次／二次供水温度 | 只接受固定字段，数值必须有限 |
| `topology` | 已知同Pod供电与CDU支路联系，逐任务列出Pod | 不使用真实故障名识别耦合类型 |
| `agents` | 公开所属队列、游标、忙碌目标、可计算完成时刻及静态移动／服务成本 | 未来完成时间是计划，不是未来观测 |

早期没有遥测或专业检查时，某些专业信号确实不可用。`task_signal`返回`None`和原因，决策另列`unavailable_target_signals`。不可评分的目标不进入CHECK排序；对受顺延影响但信号缺失的其他任务，单列使用冻结的0.05不确定性成本参数，既不宣称正常，也不称为校准风险概率。

## 3. 实际更新顺序

在已有环境中，每个5秒步先执行已提交动作；完成移动和服务后生成合格测量，随后接收该步公开遥测，更新观测器；30秒栅格采集因果历史并按冻结频率运行CVAE，再用当前新测温度覆盖缓存。下一次派单前读取新公开包。

`ObservedTask`只包装预测函数记录纯输出，不改变原有方程、动作与测量更新。三条旧完整记录按原动作重放，专业测量和完整返回证书与原记录一致；因此补充时间戳没有改变旧执行。

所有读数检查`context_cutoff <= target/produced_time <= decision_time`，年龄必须等于当前时刻减时间印记。纯CVAE输出不会因为缓存被遥测覆盖就重新标成“刚运行过模型”。专业确认、远程遥测和模型预测也不会相互冒充。

## 4. 隐藏信息与异常数值边界

适配器不读取过程数组、真实异常窗口、情景、故障起点或最终测试统计。已知设备关键度与拓扑是原任务公开配置，不能解释为学习到的故障概率。

新白名单在读数、任务、遥测、拓扑和嵌套队列成本层均拒绝附加字段。未来测量、非法单位／时间、不相容成本表、NaN／无穷数、非正时限与周期均不允许进入评分。未来计划完成时间可以大于当前时间，但不能伪装成已取得的测量。

完整模拟环境仍保存真值用于生成合法观测和评价，这是仿真执行层；在线控制只得到适配后的公开包。`queue_oracle`继续独立，仅用于事后核对，没有被新控制器导入。

## 5. 当前证据范围

本轮补的是输入可得性和因果时序。8.711502kg/s等数字来自冻结模型与旧动作的真实重放，不是用后来异常窗口填入。首次集群包遗漏PPO校验清单的失败保留，修复仅补材料；审查后又修复降温任务预筛、数值校验及无效否决条件，分别保留源版本和试跑。

新接口完整并不证明CVAE独立有益，也不证明风险代理可靠。后续需要在预先冻结的新实例上评价；本轮不重新训练CVAE/PPO或调用Qwen。
