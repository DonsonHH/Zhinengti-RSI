# Zhinengti-RSI 最新进度与研究方向审查

审查基准：2026年10月29日 · GitHub main · 提交 269fa56b

这次仓库有了明显变化。与之前停留在 M8 的状态相比，项目已经推进到 M9–M12，并进一步完成 M12-C1-B0，不再只是研究几个执行者如何重访检查点。

最重要的变化是：项目已经开始补齐导师和学长要求的系统建模、动态风险估计、异质巡检和 RSI 外层改进，并且针对效果不佳的问题连续做了多轮验证。

但当前也进入了一个很重要的研究决策期：需要判断究竟是继续优化模型，还是重新检查任务定义、可观测信息与改进空间是否合理。

我倾向于后者。下面会特别区分已经验证的成果、仍然存在的问题，以及哪些优化值得继续投入。

## 一、目前做到什么程度了？

## 二、当前最需要纠正的四个问题

### 1. 状态估计准确，不等于能够提前发现异常

最新 C1-B0 的同轨迹测试，已经很清楚地暴露了这个问题。

| 估计器     | 柜温 RMSE | 未直接观测热点召回 |
| ------- | ------- | --------- |
| 测量保持    | 1.344°C | 72/110    |
| 简单线性外推  | 1.407°C | 92/110    |
| 名义物理估计  | 0.825°C | 46/110    |
| 历史 CVAE | 0.905°C | 0/110     |

这里的110个样本是未当前直接观测的异常节点—时刻组合，并非110次独立故障。

这组结果很值得重视：CVAE 的平均误差并不差，但它在该测试中没有识别出未直接观测的热点。说明以全节点平均 MSE/RMSE 为主的训练目标，可能没有充分关注稀少的局部异常。

建议调整：

将温度平均误差与异常检出能力拆开评估，增加异常区域条件误差、热点 Precision/Recall、检测提前量和漏报后果指标。可以再对比加权损失、异常感知训练和物理残差建模，但必须使用新的训练、验证和测试划分。

不建议直接升级 Transformer 或更大 VAE，因为当前首先要弄清楚：模型究竟缺少异常信息，还是已经有信息却被训练目标平均掉了。

### 2. 当前补查评分器，没有真正学习“什么时候检查”

这是我从最新代码中看到的最直接、最值得修正的算法问题。

在 `src/patrol_rsi/inspection_value.py` 中，选择逻辑本质上是：

- 每个派单时刻给合法补查候选计算一个分数。
- 一旦候选分数超过阈值，就选择其中分数最高的。
- `used=True` 后，本次1800秒巡检不再允许额外补查。

然而代码没有显式比较：

\\[ V\_{\text{check now}}(s_t) \quad \text{和}\quad V\_{\text{wait}}(s_t) \\]

所以它学到的实际上更接近“当前候选中哪一个值得检查”，而不是“现在是否值得用掉唯一一次补查机会”。

结果也印证了这个局限：所有实际启用的补查均在5–30秒发生，导致后期真正出现异常时，没有机会再进行额外干预。

当前选择逻辑与建议修改

当前

出现可选候选

分数超过阈值

立即补查并耗尽额度

建议

出现候选及风险线索

比较现在查与等待的价值

补查或保留未来机会

这是一个典型的有限资源下的时序决策问题。可以从简单的等待门槛或有限视野规划开始，再考虑 Optimal Stopping、选项价值模型或强化学习。

重点不是立即做一个更大的网络，而是把缺失的决策选项补进去。

代码入口：[inspection_value.py](https://github.com/DonsonHH/Zhinengti-RSI/blob/main/src/patrol_rsi/inspection_value.py?utm_source=chatgpt.com) · [value_run.py](https://github.com/DonsonHH/Zhinengti-RSI/blob/main/src/patrol_rsi/value_run.py?utm_source=chatgpt.com)

### 3. 异常线索太弱，模型即使会决策也可能无从判断

最新的线索质量审计显示：

C1-B0 的未确认公开线索候选

# 3,771

触发线索的候选实例

# 54

符合新增有效确认条件的实例

在该审计定义下，54/3,771≈1.43%。候选存在大量时间与设备重复，不能将其直接解释成独立告警的真实精确率。

这意味着存在大量不具有新增确认价值的线索触发。

此时单纯增加 LLM 分析步骤或者提示词细节，可能只会让模型在质量较差的信息上进行更复杂的推断。

需要优先检查温度趋势、热模型残差、测量新鲜度、专业告警证据、跨系统故障传播等信号，究竟哪些能提供比单纯检查年龄更好的异常辨识度。

### 4. RSI 机制已经实现，但实际贡献仍然没有成立

M12-B 是目前最值得参考的 RSI 对照实验之一。

| M12-B 方法  | 漏检记录 / 42 |
| --------- | --------- |
| 固定巡回      | 14        |
| 固定改进器，3候选 | 12、12、12  |
| 随机元协议     | 14、12、14  |
| 模型元协议     | 12、14、12  |

42条记录实际对应21段底层异常在两档噪声下的重复评价。

固定改进器生成的流程，在这批样本上取得了小幅改善；但是能够更新自身协议的改进器，反而没有稳定超越固定版本。

更重要的是，M12-B 的最终保留程序没有实际调用 PPO，替换 CVAE 也没有改变漏检与等待结果。

因此，现阶段要避免把“系统包含 VAE、PPO、LLM”误写成“三个模块协同带来了性能提升”。

这不意味着这些模块没有研究价值，而是还缺少证明它们在同一最终任务上具有独立贡献的实验。

## 三、对照导师和学长要求，哪些还没有真正完成？

与 M8 相比，方向已经纠正了不少，但有几个关键目标仍需要明确界定。

| 导师关心的目标    | 最新进展                         | 剩余缺口               |
| ---------- | ---------------------------- | ------------------ |
| 配电—制冷—自控耦合 | M9 已实现降阶故障传播                 | 缺少现场参数标定和独立物理模型验证  |
| 动态风险热点图    | M9–M10 已实现                   | 预测热点的实际召回与可信度不足    |
| 异质多智能体     | M11 已区分四类专业任务、资格和服务时间        | 跨专业任务交接、动态资源调整还不完善 |
| 大型设施扩展     | 已测试4,096柜过程模型、3,200柜 GW 补充情景 | 尚未证明完整调度系统的规模可扩展性  |
| 原论文 VAE 改进 | 已有温度 CVAE 及横向估计比较            | 仍缺少完整原论文复现和稳定的任务收益 |
| RSI 自改进    | M12 已有实际模型提案及元协议实验           | 尚未获得可靠的递归改进优势      |
| 可投稿论文      | 有冻结实验、负结果、审计和研究报告            | 需要收敛到一个能被实验证明的核心创新 |

另外，M10 的 GW 场景已经把 G 明确解释为 GW 供电规模。但现有1,000MW供电预算的模拟工况，实际最大输入只有约581MW，不能据此宣称验证了1GW满载运行。

这不是当前最急迫的问题。相比继续扩大机柜数，更需要让现有系统中的估计、调度与改进机制真正产生可验证的增量。

## 四、我建议下一步按照这个顺序推进

P0：先验证当前任务到底还有多少可优化空间

用离线反事实分析建立一次补查的全回合收益参考，考虑其他任务因此遭受的损失，而不是只看目标是否被发现。

尤其要区分：没有足够线索、存在有效动作但选错时机、以及巡检资源确实不够三种情况。

验收：形成按故障事件分类的“可检测—可行动—可改善”表，并核验全程路线可行性。

P0：完成 M12-C1-B1 的补查时机实验

增加“继续等待并保留额度”动作。先做固定等待门槛和有限视野方法，再比较已有评分器。尽量在同样的补查额度、专业资格、完整返回约束下评价。

验收：在新的独立物理异常实例中，减少漏检或加权发现等待，同时不增加重访违约。

P1：单独修复异常信息质量

比较温度趋势、物理残差、测量历史和跨系统线索的辨识能力。尤其检查 CVAE 为什么在新测试中遗漏全部110个未直接观测热点实例。

验收：在固定观测预算下，报告异常事件级的召回、误报、提前量和不同故障类型的表现。

P1：再将真正有效的技能接回 RSI

一旦补查技能在独立任务上证明有效，就固定工具集合，让 Qwen3-8B 修改调用条件、诊断流程与技能选择。

同时比较人工固定、随机搜索、固定 LLM 改进器和可更新改进器，并把元改进准备成本计入总预算。

验收：在新任务上检验自动提案是否更有效，并将任务提升与递归改进提升分开。

P2：论文证据与工程交付收口

整理原论文基线与新域方法的区别、统计独立性、消融、适用范围和成本。增加自动化 CI；仓库目前没有 GitHub Actions 运行记录、正式 Release 或许可证，也缺少可直接公开复现的部分模型权重。

验收：形成可重复的核心实验包和一份独立于阶段流水账的论文方法与结果草稿。

## 五、哪些方向暂时不建议继续投入？

不建议马上扩大网络或开展更多盲目训练。 现在的问题是决策定义、线索质量和有效动作机会，而不仅是模型容量。更大的 PPO、CVAE 或 LLM 不能自动弥补这些缺口。

不建议继续堆叠更多机房物理细节。 M9 的模型已经足够支撑目前的受控实验。下一步更有价值的是向导师确认现实中哪些异常需要巡检介入、传感器可获取什么数据、设备异常能否通过现场检查得到有效确认，再用这些信息修正模型。

不建议为了证明 RSI 而不断增加元更新轮数。 在底层工具尚未稳定优于固定巡回时，增加改进器复杂度只会增加归因困难。

以上进度条是根据仓库证据作出的定性判断，不是正式的量化成熟度评分。

当前项目最大的优势是实验纪律比较好：冻结设计、失败记录、完整轨迹重放、强基线和负结果都保存了下来。尤其是最近几轮，没有把“有模型调用”误当成“模型有贡献”。

目前最大的风险是项目持续增加工程模块与实验阶段，却始终没有形成一个能稳定优于强基线、且归因清楚的核心方法。

所以我建议把接下来工作的中心问题收敛成：

> 在已知专业检查资格、重访时限和有限额外检查预算下，智能体能否利用不完整的设备风险线索，学习何时检查、何时等待，再通过经验驱动的工作流改进持续提高异常发现效率？

这个研究问题直接承接 C1-B0 的失败结果，也符合导师强调的多智能体、风险感知和 RSI 路线。

下一步最值得做的不是 M13 大规模训练，而是先完成一次针对“补查时机与线索信息价值”的严格对照实验。 如果它能获得稳定收益，再将有效技能接回 RSI；如果不能，就需要进一步修正问题设定，而不是继续叠加模型。

我这次核对了最新代码、报告、提交和仓库记录，但没有重新在 Slurm/GPU 环境执行所有训练或独立审计，因此对测试通过情况的判断仍以仓库中保存的执行证据为依据。
